# Building and Verifying from Source

[简体中文](BUILDING.md) ｜ English ｜ [한국어](BUILDING.ko.md)

This guide is for anyone who wants to build the Android client or contribute to its development. To install a published version, use [GitHub Releases](https://github.com/yamatosaki/yahagi-kancolle-browser/releases). The source on the default branch may be ahead of the published app. If you need the source for a specific release, check out the corresponding tag from the release page and follow the configuration at that tag.

## Development Environment

The current [CI configuration](.github/workflows/ci.yml) uses:

- Flutter **3.44.8 stable**. Dart is included with Flutter; see `pubspec.yaml` for the version constraint.
- JDK **17**. Set `JAVA_HOME` to JDK 17 when running the native Android tests.
- The Android SDK, command-line tools, and build components with their licenses accepted. The Flutter SDK determines the `compileSdk` and NDK versions; see `android/app/build.gradle.kts`.
- Git. Python is not needed to build an APK; the full data checks additionally require Python 3 and Pillow.

Install these tools, then check your environment with `flutter doctor -v`. You can review and accept the Android licenses with `flutter doctor --android-licenses`. The first build needs to download dependencies for Flutter, Pub, Gradle, and Android.

## Get the Source and Build a Debug APK

Run the following commands in a terminal:

```sh
git clone https://github.com/yamatosaki/yahagi-kancolle-browser.git
cd yahagi-kancolle-browser
flutter pub get
flutter build apk --debug
```

The generated APK is at `build/app/outputs/flutter-apk/app-debug.apk`. With a device connected for debugging, you can also use `flutter run`.

Debug builds use a debug signing key generated automatically on your machine. They do not require the maintainer's signing keys, account data, game databases, or backup files. Machine-specific configuration, such as the Android SDK path, is generated by the tools and should not be committed to the repository.

The repository includes the required asset snapshots, fonts, Gradle Wrapper, and `pubspec.lock`. You do not need to clone a data repository or run data-fetching tools first. `flutter pub get` downloads the locked dependencies and generates local configuration; do not replace it with `flutter pub upgrade` for initial setup. This repository provides an Android project; third-party iOS ports have a separate build setup.

An APK signed with your key cannot update an official installation signed with a different key. To install both versions, change the application ID as described in the [Customization Guide](CUSTOMIZING.en.md). If you uninstall the existing app instead, export the records you need first: uninstalling clears app data. Use the same key and keep or increase the version code when updating your own build later.

## Build with GitHub Actions

You can also fork this repository, enable Actions in your fork, and open **Actions → CI → Run workflow**. Select your default branch and start the run. After all checks and the debug build succeed, download `yahagi-debug-apk` from the run's Artifacts section and extract `app-debug.apk`. Artifacts are retained for 7 days; run the workflow again if they expire. Initial builds and dependency downloads can take time. Check the run logs if it fails.

This route needs no maintainer signing secrets and produces a debug-signed APK. It cannot update an official installation with a different signature. The temporary Actions environment can also generate a different debug key on each run, so one run's APK may not install over another's. For long-term use or independent distribution, configure your own persistent release key.

## Verification Commands

Run the checks corresponding to CI from the repository root:

```sh
python -m pip install pillow
python -m unittest tool.test_check_repository_hygiene -v
python tool/check_repository_hygiene.py
python -m unittest tool.test_build_sortie_release tool.test_build_enemy_release tool.test_verify_data_release -v
dart run tool/verify_data_release.dart
dart format --output=none --set-exit-if-changed lib test
flutter analyze
flutter test
```

To run the native Android unit tests in Windows PowerShell:

```powershell
.\android\gradlew.bat -p android :app:testDebugUnitTest --console=plain
```

On Linux or macOS:

```sh
chmod +x android/gradlew
./android/gradlew -p android :app:testDebugUnitTest --console=plain
```

Some integration tests use raw samples kept only on local development machines. These tests explicitly skip when the samples are absent from a public checkout. The public tests using synthetic data do not require real accounts or game API dumps. Do not add raw data to the repository just to run the local integration tests.

## Release Signing

`flutter build apk` selects release mode by default. This mode requires your own signing configuration. When first checking whether the source builds, use the `--debug` command above.

To make your own release APK, create a personal signing key outside the repository. This PowerShell example uses the JDK's `keytool`, which prompts for passwords and certificate details:

```powershell
New-Item -ItemType Directory -Force "$env:USERPROFILE/.yahagi-custom"
keytool -genkeypair -v -keystore "$env:USERPROFILE/.yahagi-custom/yahagi-custom.jks" -alias yahagi-custom -keyalg RSA -keysize 2048 -validity 10000
```

Manually create `release-signing.properties` in the same directory, using your own absolute path and passwords. Use forward slashes in the path. These values are placeholders:

```properties
storeFile=C:/Users/yourname/.yahagi-custom/yahagi-custom.jks
storePassword=YOUR_STORE_PASSWORD
keyAlias=yahagi-custom
keyPassword=YOUR_KEY_PASSWORD
```

Set `keyPassword` to the actual key password. If key generation did not configure a separate one, this is normally the same as `storePassword`.

Run from the repository root in PowerShell:

```powershell
$env:YAHAGI_SIGNING_PROPERTIES = "$env:USERPROFILE/.yahagi-custom/release-signing.properties"
flutter build apk --release
```

On macOS/Linux, use a directory under your home folder and run `export YAHAGI_SIGNING_PROPERTIES="$HOME/.yahagi-custom/release-signing.properties"` before building. The APK is at `build/app/outputs/flutter-apk/app-release.apk`. Keep your key and passwords for future updates. See `android/app/build.gradle.kts` for the signing implementation.

Do not commit keys, signing configuration, local SDK configuration, app packages, logs, or record backups. For third-party code and resource licenses, see [THIRD_PARTY_NOTICES](THIRD_PARTY_NOTICES). For contribution requirements, see the [Contributing Guide](CONTRIBUTING.en.md).
