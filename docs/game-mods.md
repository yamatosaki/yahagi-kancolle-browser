# 魔改包使用说明

入口：**工具箱 → 魔改**。

## 第一次使用

1. 在制作网站导出 `cache.zip`，保留 ZIP 文件，不需要自己解压。
2. 点击“导入魔改包”，检查预检中的可用资源和不支持项目，再确认导入。
3. 新包默认关闭，可用资源默认选中。开启魔改总开关，再开启需要的包。
4. 进入包详情，可以分别选择资源、调整包的优先级，也可以删除这个包。
5. 点击底部“应用并刷新游戏”，统一应用选择。游戏未打开时，配置会用于下次打开游戏。

支持 `kcs2/resources/ship/`、`kcs2/img/` 和 `kcs2/resources/furniture/` 下符合游戏路径的 PNG，以及 `kcs/sound/kc.../数字编号.mp3` 或同编号的 `.wav` 语音。路径可带 `cache/` 前缀，PNG 可带 `.hack` 标记。ZIP 文件名可以带日期或其他前缀。

可以在 ZIP 中保留一层共同的外层文件夹，例如 `包名/kcs2/img/common/bg_map/bg_h.hack.png`。所有文件须位于该文件夹下，且其下至少包含一个有文件的 `kcs/`、`kcs2/` 或 `cache/` 目录。ZIP 条目名默认按 UTF-8 读取。条目未标记为 UTF-8 且文件名无法按 UTF-8 解码时，会尝试使用 GBK。

同一目录中的 `bg_h.png` 和 `bg_h.hack.png` 可以一起导入。预检会提示优先采用 `.hack.png`，导入后只显示一个资源。其他映射到同一目标的重复条目会导致导入失败。

`bat.zip` 是制作过程中的中间文件，需要先在制作网站转换成 `cache.zip`。7z 分发包需要先转换为 ZIP，保留内部的 `kcs/`、`kcs2/` 目录。

支持与舰娘立绘匹配的 `*.config.ini`、`*.config.json` 坐标配置。同一份坐标的两种格式合并为一个开关，详情列出源文件；例如伊47包的4个文件显示为2张立绘和1组坐标。可分别选择普通立绘、中破立绘、坐标及语音。

需要 JSON 配套的图集和脚本暂不支持。无法确认对应船只的坐标会注明原因，相关图片会停用；坐标数值损坏或两种格式互相矛盾时会拒绝导入，保留现有包。有效 PNG 结束后的多余尾部数据会在完整校验通过后从导入副本中清理，并在预检中提示；原压缩包保持不变。

## 立绘坐标

坐标可以调整母港、战斗、地图、改造等场景的位置。配置在游戏重新读取启动数据时写入本地响应，原始游戏请求和记录抓取数据保持原样。坐标不会直接改写图片，也不修改服务器数据。

图片和坐标有各自的开关：一般使用作者提供的组合即可；单独关闭坐标会恢复游戏原有位置，图片仍可替换。多个包调整同一船只时，逐个坐标字段按列表上方的包优先；互不重叠的字段可以同时使用，详情会标出部分覆盖。

开启并应用坐标后，先显示“等待游戏读取”。只有游戏的启动数据消费者实际读到已修改坐标，才显示“已写入游戏坐标”。这表示坐标数据已送入客户端，最终场景画面仍以游戏实际显示为准。旧版导入时被标为不支持的坐标包需要重新导入。

## 语音替换

语音与图片一样，可以按包、按资源分别选择，再统一应用刷新。语音条目显示对应游戏编号；多个包替换同一语音时，列表上方的包优先。

只有能够直接对应游戏请求路径的数字编号 MP3 或 WAV 可启用。例如 `kcs/sound/kc.../123456.wav` 会替换游戏的同编号 `123456.mp3` 请求，返回原WAV音频及正确类型，无需自己转成MP3。文件来源路径会保留，MP3与WAV替换同一编号时沿用包优先级；同一包内出现两个相同目标则拒绝导入，避免选择不明确。

WAV支持单/双声道PCM（8、16、24、32位）和32位IEEE浮点，包括WAVE_FORMAT_EXTENSIBLE。压缩WAV、64位浮点、损坏或截断的音频不支持。中文命名的备用语音（例如“击沉.wav”）仍需要正确的游戏数字编号，不能只凭名称自动决定替换位置；`kcs2/sound/` 等未确认路径也会标明原因。旧版导入的WAV不会自动启用，需要重新导入该包以检查支持。

游戏可以分段读取音频。详情会区分已提供部分音频与已完整提供资源；这些是数据加载状态，实际是否播放还取决于游戏是否触发相应语音。

## 状态怎样看

| 状态 | 含义 |
| --- | --- |
| 包开关 / 资源开关 | 当前保存的选择；总开关关闭时仍保留这些选择 |
| 等待应用 | 选择与当前游戏使用的配置不同，需要统一应用 |
| 尚未命中 | 当前会话尚未完整提供这个资源；进入相应画面后才可能加载 |
| 已提供部分音频 | 已向游戏提供部分语音字节，可能处于预加载或分段加载中 |
| 已提供资源 | 当前会话已完整提供资源；语音的多个完整分段累计覆盖全部文件也算完整提供，实际播放由游戏决定 |
| 等待游戏读取坐标 | 坐标已启用，当前会话尚未确认读取对应启动数据 |
| 已写入游戏坐标 | 游戏启动数据消费者已读到本次会话的坐标；与图片、语音读取分开统计 |
| 被其他包覆盖 | 多个已开启的包选择了同一资源，列表上方的包优先 |
| 部分坐标被覆盖 | 这一组仍有字段在使用，重叠字段由上方包提供 |
| 读取失败 | 后续请求回退到普通加载路径；修复或重新导入后再应用 |

详情区同时显示当前提供者和下次应用后的提供者。关闭某个资源后，同一路径可以由下一个开启的包提供；没有其他包时恢复原资源。

如果无法确认游戏刷新目标，页面会提示刷新受阻，并保留等待应用的选择。不要把保存选择当作已经刷新游戏。

### 同步软件界面的头像

“同步到软件界面”默认开启，单独保存此设置。开启后，编队简报、舰娘详情和持有一览使用当前已应用魔改中的对应头像；包和资源选择仍需应用后才统一更新。这个同步开关立即生效，关闭后使用原头像，游戏内魔改继续沿用原配置。

优先使用对应舰娘的魔改头像或横幅。各资源类型使用统一的固定裁切规则：`remodel` 沿用原头像规则，横幅使用固定横幅框，`character_full` 角色画布使用顶部居中方框，普通 `full` 立绘保持左上方框。保留原界面的圆角、背景与渐隐，不对舰娘或魔改包单独适应人物位置；缺少可用图片或读取失败时恢复原头像。官方图片缓存与魔改头像分开处理，软件显示不会计入游戏资源加载统计。

魔改包也可能附带其他舰娘的原版角色图，启用并应用后同样会参与同步。`character_full` 与普通 `full` 的画布构图不同，不能共用左上截框，否则部分头像可能只显示帽沿或舰装。关闭同步仍直接使用原头像组件及原来的裁切方式。

## 删除与还原

- **删除单个包**：在包详情中删除，确认后卡片变为红色并标记“待移除”；文件会在底部应用成功后清理。其他包保留。
- **取消未应用修改**：点击“应用并刷新游戏”左侧的“取消”，撤回尚未应用的删除、开关、资源选择和优先级，当前游戏不刷新。新导入的包仍保留在列表中，但恢复为关闭、未选择资源的状态。已经应用成功的删除不能通过此按钮撤回。
- **全部还原**：确认后清空全部魔改包和选择，并尝试刷新恢复原资源。刷新受阻时保留待处理状态，按提示重试。

全部还原只清理魔改数据，保留登录信息、普通游戏缓存、设置和记录。关闭魔改总开关可以临时恢复原资源并保留包，之后仍需应用刷新。

## 导入限制

支持普通未加密 ZIP。压缩包最大 256 MiB，最多 20000 个条目，解压总大小最大 1 GiB，单文件最大 64 MiB。损坏图片、MP3 帧或 WAV 结构校验失败、不安全路径、符号链接、分卷或 ZIP64 等会导致导入失败。失败时保留已有包。

Android 需要支持文档启动脚本和网页消息的 WebView。暂不支持的平台会在页面内说明。

## 坐标接入的技术验证

坐标按配置原值写入客户端的 `api_mst_shipgraph`，不统一乘以 1.5。二期坐标生成器直接将 API 数组导出为 INI 的 `left/top`，游戏客户端的 `ShipGraphModel` 也直接将数组读为绘图坐标。[生成器源码](https://github.com/ArchmageTony/KanColleCoordinatesMaker_v2/blob/master/src/main/java/org/at/FindOutData.java)

`api_weda` 是正常立绘面部矩形的左上角，`api_wedb` 是其宽高；受损立绘使用 `api_wedc/api_wedd`。只覆盖包内明确给出的字段，保留其他字段、舰名、版本及资源文件标识。伊47包给出的 `api_weda=[0,0]` 按原值保留，不推测新的面部位置。

可选的 `test/game_mod_coordinate_game_consumer_test.dart` 在运行时从本地忽略目录的已解码游戏脚本抽取实际 `APIBase/GetDataAPI/ShipGraphModel/ShipGraphModelHolder` 和母港初始化函数，游戏代码不写入测试夹具。网络、图形库及其他模型使用测试替身；因此结果证明启动数据在模型消费前得到改写、原始抓取和请求参数保留，以及真实 PNG 尺寸进入呈现锚点计算，不能代替完整游戏画面的视觉验收。

本地运行需要显式设置 `YAHAGI_GAME_DECODED_JS`、`YAHAGI_GAME_START2_JSON`、`YAHAGI_REAL_MOD_ZIP`、`YAHAGI_REAL_VOICE_MOD_ZIP`；可用 `YAHAGI_TEST_PYTHON` 指定 Python，通过 `YAHAGI_GAME_CONSUMER_REPORT` 保存 JSON 报告。环境缺失时测试明确跳过。命令为 `flutter test --no-pub test/game_mod_coordinate_game_consumer_test.dart`。
