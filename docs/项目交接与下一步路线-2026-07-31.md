### 第三优先级：任务数据本地持久化

当前任务数据来自 `/kcsapi/api_get_member/questlist`。应用可以正确显示已接受任务，但解析结果只保存在内存中。应用被结束或重新安装 APK 后，任务页面会回到「等待任务数据」，直到玩家再次进入游戏并打开任务列表。

目标：

- 捕获任务列表后，保存经过解析和脱敏的 `GameQuest` 数据。
- 应用重新启动后，先恢复最后一次任务快照。
- 新的任务接口到达后，用服务器数据更新本地快照。
- 保存更新时间、数据版本和任务字段，不保存原始接口正文。
- 不保存 Cookie、`api_token`、请求头、登录地址或其他账号凭据。
- 损坏或版本不兼容的快照应安全忽略，页面退回「等待任务数据」。

建议新增：

- `lib/src/quest/quest_store.dart`
  - 定义 `QuestStore` 接口。
  - 提供读取、写入和清除任务快照的方法。
- `lib/src/quest/shared_preferences_quest_store.dart`
  - 使用项目已经依赖的 `shared_preferences`。
  - 只保存序列化后的任务模型，不保存捕获事件原文。
- `test/quest_store_test.dart`
  - 覆盖保存、恢复、损坏数据、版本不匹配和空数据。
- 修改 `GameStateController`
  - 启动时恢复任务快照。
  - reducer 处理 `questlist` 后异步保存新快照。

验收标准：

1. 打开游戏任务列表，任务中心出现任务。
2. 完全结束应用后重新打开，不进入游戏任务页也能看到上次任务。
3. 再次打开游戏任务列表后，任务状态按最新接口更新。
4. 本地存储中不存在 Cookie、Token、原始接口正文或完整登录 URL。
5. 现有测试全部通过，`flutter analyze` 无问题。

### 第四优先级：任务中心第二阶段

- 不读取 Cookie。
- 不修改、阻断、代理、重放游戏请求。
- 不自动点击、补给、编成、出击或领取任务。
- 提供「游戏模式（默认）」与「纯浏览模式」。
- iOS 只预留 `GameCapturePort` 接口，未实现 WKWebView 原生桥接。

## 4. 已知限制与注意事项

### 4.1 首页和设置尚未正式化

游戏首页右侧仍混有技术测试状态卡。正式设置一级菜单尚未实现。下一位 Agent 应以本文档第 1 节为准完成迁移，不要继续扩展 `_InformationPanel` 中的测试卡片。

### 4.2 项目当前不是 Git 仓库

项目目录中没有 `.git`。下一位 Agent 不应假定可以使用 `git diff`、分支、提交或回退。

在初始化 Git 前，必须先征得用户同意，并避免把构建产物、IDE 缓存和账号相关数据加入仓库。

### 4.3 README 已经过时

根目录 `README.md` 仍将项目描述为早期技术原型，并写着舰队、战斗和任务尚未接入。实际代码已经远超该阶段。

不要以 README 作为当前功能真相。当前状态以本文档、`docs/superpowers/specs/` 和实际代码为准。后续可以单独安排一次 README 更新。

### 4.4 业务状态主要保存在内存

捕获的舰队、任务、远征、入渠、建造和战斗状态会随应用进程结束而丢失。WebView Cookie 由 Android System WebView 自己管理，但应用代码不读取 Cookie。

任务数据持久化是当前最明确的下一步。其他状态是否持久化，应逐项评估数据敏感性和过期策略。

### 4.5 任务进度不是精确百分比

游戏任务列表只提供未达到 50%、达到 50%、达到 80% 和完成等状态。当前 UI 使用区间显示，不应改成虚假的精确百分比。

### 4.6 Android 优先，iOS 尚未落地

不要在没有设计和验证的情况下复制 Android 注入方案到 iOS。iOS 需要单独实现 WKWebView 消息桥、来源校验、脚本安装时机和兼容性测试。

### 4.7 无法承诺零封号风险

当前方案坚持只读、无 Cookie 读取、无请求修改、无自动操作，但网页脚本理论上仍可能感知 XHR／Fetch 包装。文档和 UI 不应使用「绝对安全」「不会封号」等承诺。

## 5. 开发纪律

下一位 Agent 修改代码时应遵循：

1. 先阅读相关规格和现有测试。
2. 行为变化先写失败测试。
3. 确认测试因目标行为缺失而失败。
4. 编写最少实现。
5. 运行目标测试。
6. 运行全部测试和 `flutter analyze`。
7. 构建 APK。
8. 安装到模拟器检查实际布局。

不要：

- 删除用户已有文件。
- 清理整个构建目录来解决普通问题。
- 更改捕获安全边界而不写规格。
- 保存原始 KCSAPI 正文、Cookie、Token 或登录凭据。
- 自动执行游戏操作。
- 用虚构数据替代服务器没有提供的数据。
