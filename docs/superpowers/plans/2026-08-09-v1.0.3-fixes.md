# Yahagi 1.0.3 修复实施计划

> 设计依据：`docs/superpowers/specs/2026-08-09-v1.0.3-fixes-design.md`

## 批次 A：纯 Dart UI 与状态修复

1. 推荐比例
   - 先在 `test/layout_settings_controller_test.dart` 和设置页组件测试中加入开启时固定显示 35%、滑条禁用、关闭后恢复保存值的失败断言。
   - 修改 `lib/src/settings/layout_settings_controller.dart`、`lib/src/settings/screen_settings_page.dart` 和本地化 ARB。
   - 运行相关 Flutter 测试。

2. 首页排序
   - 抽取/复用可测试的重排函数，加入中间项拖至末尾、末尾项向上的失败测试。
   - 修改 `lib/main.dart`，去掉对新索引的重复递减。
   - 运行排序相关测试。

3. 入渠同步
   - 在 `test/game_state_reducer_test.dart` 增加入渠开始、高速修复成功响应不含 `api_data` 的失败用例。
   - 修改 `lib/src/game_state/game_state_reducer.dart` 的解码白名单。
   - 运行 reducer 测试。

4. 首页机制胶囊
   - 在舰队状态胶囊组件测试中加入机制识别和同规格 `MiniBadge` 的失败断言。
   - 修改 `lib/src/fleet/fleet_ship_status_capsule.dart`，复用 `combat_mechanism.dart`，首页只展示最高优先级机制。
   - 运行舰队组件测试。

5. 任务简报
   - 为未同步、确实为空、服务端计数校正、领取/放弃后移除以及详情页精确计数加入 reducer/组件失败测试。
   - 扩展 `GameState` 的任务同步元数据和服务端计数，更新 reducer、持久化和任务 UI。
   - 首页仅保留状态胶囊及总数；详情页按 poi 混合模型展示精确计数或阶段进度。
   - 运行任务相关测试。

完成批次 A 后提示黄色闪电 Hot Reload；若状态模型新增字段未正确刷新，则提示绿色 Hot Restart。

## 批次 B：退出账号

1. 为 `GameBrowserPort` 会话清理协议和设置页确认/成功/失败流程加入失败测试。
2. 扩展 `lib/src/browser/game_browser_controller.dart` 与 `lib/src/game_webview.dart`：清 Cookie、Local Storage、缓存并回到登录入口。
3. 替换 `network_settings_page_new.dart` 的占位提示。
4. 运行控制器和组件测试。

若仅改 Dart WebView API，提示绿色 Hot Restart，以确保端口重新绑定。

## 批次 C：GotoBrowser 式解除 60 FPS 上限

1. 用 JVM 测试固定 GotoBrowser 正则替换行为、未匹配回退和目标 URL 识别。
2. 将 Flutter 设置模型从三态迁移为单一布尔开关，并测试旧值迁移。
3. 在 Android WebView 请求拦截链中加入独立于 gadget 绕过开关的主脚本获取与补丁逻辑；复制必要请求头，失败时交回原 WebViewClient。
4. 删除运行时 document-start FPS 注入方案及旧测试。
5. 运行 Flutter 设置测试和 Android JVM 测试。

此批次涉及 Kotlin 和原生通道，完成后提示停止 Debug 再重新运行。

## 批次 D：键盘、版本与总验证

1. 将 AndroidManifest 的软键盘模式改为 `adjustPan`，检查 manifest 合并结果。
2. `pubspec.yaml` 提升至 `1.0.3+4`（若当前构建号检查结果不同，则在现值上递增）。
3. 运行格式化、相关 Flutter 测试、完整 `flutter test`、`flutter analyze`、Android JVM 测试。
4. 连接 Android 设备时做登录键盘、退出、入渠、高刷四项人工验证；设备未连接则明确列为待用户复验项。

最终只提示停止 Debug 后重新运行一次；不在此阶段构建 APK，发布时再统一打包。
