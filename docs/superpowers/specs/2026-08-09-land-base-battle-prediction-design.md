# 基地航空战预测与基地空袭损伤设计

## 背景与目标

当前“未卜先知”战斗引擎虽然尝试解析 `api_air_base_attack`，但缺少真实数据包回归测试，玩家反馈基地航空队炸伤或击沉敌舰后，敌方剩余 HP 与预计胜败没有随之变化。同时，应用尚未建立基地航空队状态，也没有消费 `api_get_member/mapinfo` 中的 `api_air_base`，因此无法处理 `api_req_map/next` 返回的 `api_destruction_battle` 基地空袭损伤。

本次改动以 POI 的数据语义为基准，实现两条相互独立但共享界面的链路：

1. 出击战斗中的基地航空队攻击参与敌舰 HP、击沉状态与预计胜败结算。
2. 基地遭空袭后，根据服务端实际返回的损伤即时展示各基地剩余 HP，并保存到本次出击结束。

这里的“基地空袭预测”是玩家在游戏动画完成前看到已经由服务端确定的结果，不推算尚未发生的随机空袭结果。

## POI 对齐基准

### 基地航空队攻击敌舰

POI 将完整战斗包追加给 `poi-lib-battle` 模拟器，并按照战斗阶段顺序处理基地喷气强袭、各波基地航空队攻击、舰队航空战、支援与后续炮雷击。`api_air_base_attack` 中的敌方伤害必须先写入敌舰状态，再计算最终剩余 HP 与预计胜败。

### 基地遭空袭

POI 在 `api_req_map/next` 中发现 `api_destruction_battle` 后，按基地编号读取：

- 初始 HP：`api_f_nowhps`
- 最大 HP：`api_f_maxhps`
- 空袭伤害：`api_air_base_attack.api_stage3.api_fdam`

基地剩余 HP 为 `max(0, 初始 HP - 空袭伤害)`。结果写入对应海域、对应基地编号的临时状态，在基地航空队详情中显示；回港后清除临时 HP。

## 范围

### 包含

- 普通与联合舰队战斗中的多波 `api_air_base_attack`。
- `api_air_base_injection` 基地喷气强袭的既有行为回归保护。
- 敌方主力与随伴舰队的基地航空伤害映射。
- `api_get_member/mapinfo` 中基地航空队基础状态的读取。
- `api_req_map/next` 中 `api_destruction_battle` 的基地损伤读取。
- 空袭结果在“未卜先知”中的即时展示。
- 本次出击期间的基地 HP 状态保存，以及回港清除。
- 畸形、缺字段与字符串形式嵌套数据的容错。

### 不包含

- 在服务端返回结果前随机模拟未来空袭伤害。
- 推算防空配装的理论制空值或概率分布。
- 新建完整的基地航空队编成、换装或补给功能。
- 改变现有战斗预测方式选择设置。

## 数据模型

新增独立的基地航空队状态模型，至少包含：

- 海域 ID `areaId`
- 基地编号 `baseId`
- 基地名称 `name`
- 行动类型 `actionKind`
- 最大 HP `maxHp`（仅出击期间可能存在）
- 当前 HP `currentHp`（仅出击期间可能存在）
- 最近一次空袭损失 `lastRaidDamage`

`GameState` 保存基地列表。基础资料来自 `api_get_member/mapinfo.api_air_base`；地图前进响应只更新当前海域内匹配基地编号的临时 HP 与损伤，不覆盖名称、行动类型等已有资料。

战斗预测模型仍只负责舰队与敌舰战斗，不把基地当作舰船。基地空袭展示使用单独的 `LandBaseRaidResult`（或等价不可变模型），由地图响应产生并附加到当前“未卜先知”导航状态，避免基地 HP 污染舰队战斗排名计算。

## 数据流

### 基地航空队攻击敌舰

1. 捕获受支持的战斗 API 响应。
2. 建立双方主力与随伴舰队初始快照。
3. 按服务端顺序遍历 `api_air_base_attack` 的每一波。
4. 分别应用 `api_stage3.api_edam` 与 `api_stage3_combined.api_edam`。
5. 对伤害数组兼容有无前导占位值的形式，并将小数伤害按现有 POI 兼容规则取整。
6. 所有基地航空波次完成后再处理舰队航空战及后续阶段。
7. 使用更新后的敌舰 HP 计算击沉状态、预计胜败与界面血条。

默认 POI 预测引擎与 Yahagi 预测引擎都必须得到一致的敌舰 HP；两种实现可以保留各自排名与 MVP 逻辑。

### 基地遭空袭

1. `GameStateReducer` 接收 `api_get_member/mapinfo`，建立或刷新基地航空队列表。
2. `api_req_map/next` 到达时检查 `api_destruction_battle`。
3. 若 `api_air_base_attack` 为字符串，先安全地进行 JSON 解码；若已为对象则直接使用。
4. 从 `api_stage3.api_fdam` 读取各基地损伤，并按 `baseId - 1` 对应 HP 数组。
5. 仅更新 `api_maparea_id` 匹配的基地；缺少本地基础资料时仍生成“第 N 基地航空队”的临时结果，保证未卜先知能够展示。
6. “未卜先知”立即切换或补充为“基地空袭”结果视图。
7. 收到 `api_port/port` 后清除临时基地 HP、最近空袭损伤和当前空袭结果；基础基地资料可由下一次 `mapinfo` 刷新。

## 界面设计

基地航空队攻击敌舰不增加新的常驻区域，直接反映在现有敌方舰船血条、击沉状态和预计胜败中。

基地遭空袭时，“未卜先知”的导航阶段显示独立的“基地空袭”区块：

- 标题胶囊：`基地空袭`
- 每个受影响基地一行：完整基地名称、`当前 HP / 最大 HP`、`损失 -N`
- 使用与现有舰船状态协调的紧凑 HP 条；严重受损使用更醒目的警告色
- 宽屏并排显示多个基地，窄屏自动纵向排列，不允许横向滚动
- 没有伤害的基地仍显示 `损失 0`，避免玩家误以为漏报

该区块显示的是本次节点的实际空袭结果。进入下一节点且没有新空袭时不重复制造新结果；基地临时 HP 状态保留到回港。

## 容错与确认状态

- `api_air_base_attack` 缺失或为空：跳过该阶段，不产生错误。
- 单个波次不是对象：记录可诊断问题并继续处理其他波次。
- 伤害数组短于舰队或基地数量：只更新可对应的位置。
- 伤害为负值、空值或非法字符串：按 0 处理。
- 计算后的 HP 约束在 `0..maxHp`。
- 联合舰队目标无法映射时，将战斗会话标记为“结果待确认”，但保留可确认的其他波次结果。
- 基地空袭数据异常时，不覆盖已有基地 HP；未卜先知显示简短的“基地空袭数据暂时无法解析”，不导致整个首页失效。

## 测试策略

### 战斗预测

- 真实形态的单波基地航空队伤害会降低敌方 HP。
- 多波攻击按顺序累计，并能击沉敌舰。
- 击沉结果会改变预计胜败。
- 普通舰队、敌方联合舰队主力与随伴目标分别正确映射。
- 有无伤害数组前导占位值都能解析。
- POI 与 Yahagi 两种预测引擎的最终敌方 HP 一致。
- 基地航空阶段早于普通航空战执行。

### 基地空袭状态

- `mapinfo` 正确建立多海域、多基地状态。
- 对象与字符串形式的 `api_air_base_attack` 都能解析。
- 多基地损伤按基地编号写入正确对象。
- 其他海域基地不受影响。
- 缺少基地基础资料时仍能生成临时展示结果。
- 回港清除临时 HP 与空袭结果。
- 异常字段不会清空既有有效状态。

### 界面

- “基地空袭”标题、基地名称、HP 与损失值正确显示。
- 零伤害与严重受损样式明确。
- 窄屏纵向换行且无横向溢出。
- 普通基地攻击后现有敌舰血条和预计胜败即时刷新。

## 验收标准

- 基地航空队炸伤或击沉敌舰后，未卜先知中的敌方 HP、击沉状态和预计胜败在同一战斗响应内更新。
- 基地遭空袭后，未卜先知立即显示每个基地的剩余 HP 与本次损失。
- 基地损伤状态在本次出击中保留，回港后清除。
- 普通舰队、联合舰队、多波攻击和多基地空袭均有自动化测试覆盖。
- 相关 Flutter 测试通过，静态分析无新增问题。
- 改动可通过常驻 Debug 的黄色闪电热重载生效；如模型结构导致当前运行实例无法正确重建状态，则明确提醒使用绿色重新运行。
