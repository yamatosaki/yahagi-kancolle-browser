# 顶部泊地计时器导航设计

## 目标

用户点击首页顶部的「泊地：时间」胶囊后，应用直接打开修理工作区的「泊地修理」详情页，并优先显示当前正在泊地修理且舰队编号最小的舰队。

## 已确认行为

- 点击胶囊时，根据最新 `GameState` 实时判断舰队状态。
- 按舰队 ID 从小到大选择第一个存在 `repairing` 舰娘的舰队。
- 第 2、3 舰队同时正在泊地修理时，打开第 2 舰队。
- 只有第 3 舰队正在泊地修理时，打开第 3 舰队。
- 没有任何舰队正在泊地修理时，仍打开泊地修理详情页，并默认显示第 1 舰队。
- 胶囊原有的长按自定义行为保持不变；点击负责导航，长按负责进入排序和筛选模式。

## 判定规则

复用 `AnchorageRepairCalculator.project` 生成每支舰队的实时投影。仅当投影中至少一艘舰娘的状态为 `AnchorageRepairShipStatus.repairing` 时，该舰队才算「当前正在泊地修理」。

该规则会自然排除以下情况：

- 旗舰不是可执行泊地修理的明石或朝日改组合；
- 旗舰、设施、配对或远征状态不满足修理条件；
- 舰队内舰娘全部满血；
- 损伤舰娘不在当前可修理舰位内；
- 损伤程度不符合泊地修理要求，或舰娘正在入渠。

舰队投影的 `elapsed` 使用当前泊地计时器经过时间。舰队是否存在 `repairing` 状态本身不依赖最低 20 分钟门槛，因此计时开始后即可正确导航。

## 组件和数据流

1. `CompactResourceBar` 为泊地计时胶囊接收并触发点击回调。
2. `WorkspaceContextHeader` 将回调从应用外壳传递给顶部胶囊。
3. `YahagiShell` 在点击时读取 `GameStateController.state` 和 `anchorageRepairStartedAt`，计算目标舰队。
4. `YahagiShell` 将修理模式设为 `RepairCenterMode.anchorage`，将目标舰队写入 `_repairCenterInitialFleetId`，再切换 `_workspaceIndex` 到修理工作区。
5. 现有 `FleetInformationCenter` 和 `AnchorageRepairView` 使用 `initialFleetId` 显示目标舰队，无需新增导航体系。

目标舰队选择应封装为纯函数，输入 `GameState` 和经过时间，输出舰队 ID；没有匹配舰队时返回 `1`。纯函数负责排序，不能依赖 `state.fleets` 的原始排列顺序。

## 交互与异常处理

- 点击隐藏状态下不存在的胶囊不会产生导航。
- 自定义编辑模式中的胶囊不触发页面跳转，避免拖动或长按时误导航。
- 如果 `GameState` 中没有舰队数据，回退到舰队 ID `1`，泊地修理页继续使用现有缺省与空状态表现。
- 导航前不修改泊地计时器、舰队状态或游戏数据。

## 测试

- 纯函数测试：第 2、3 舰队同时修理时返回 `2`。
- 纯函数测试：只有第 3 舰队修理时返回 `3`。
- 纯函数测试：没有舰队修理或没有舰队数据时返回 `1`。
- Widget 测试：点击顶部泊地胶囊会触发回调，长按仍进入自定义模式。
- 外壳集成测试：点击后进入修理工作区，模式为泊地修理，`initialFleetId` 为选出的舰队。
- 回归测试：顶部胶囊显示、计时、自定义排序和筛选继续通过。

## 非目标

- 不改变泊地修理资格、HP 恢复量或计时公式。
- 不调整修理详情页的舰队切换器和视觉样式。
- 不持久化最后一次由胶囊打开的舰队；每次点击都根据当前状态重新选择。
