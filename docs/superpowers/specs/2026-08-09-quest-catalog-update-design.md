# 任务资料库在线更新设计

## 目标

任务资料库采用与“未卜先知资料”一致的更新体验：应用始终包含一份可离线使用的内置任务资料；启动后自动检查更新；设置页提供手动检查按钮；新资料通过完整校验并安全保存后立即应用，不要求重新安装或重新打 APK。

## 范围

本功能更新任务目录的英文编号、名称、说明、奖励、完成条件和前置关系。后置关系仍由应用根据前置关系反向生成。游戏接口同步到的进行中任务及其实时进度不属于远端资料库，不会被资料更新覆盖。

本次不抽象或重构现有 FCD 地图更新模块。任务资料使用独立的 Controller、Store 和 UpdateService，接口与生命周期遵循 FCD 模块现有模式。

## 数据源和版本

- 上游：kcWiki `kcQuests` 仓库中的 `quests-scn.json`。
- 主要下载源：GitHub Raw。
- 备用下载源：jsDelivr GitHub CDN。
- 更新请求只允许预先写死的 HTTPS 地址，不接受远端重定向到未授权域名。
- 版本由上游文件对应的提交信息表示，界面显示提交日期和短提交号；本地同时保存完整提交号和内容校验值。
- 如果无法取得可信版本信息，则本次检查按网络失败处理并保留当前资料，不使用无法判定新旧的数据覆盖本地缓存。

## 启动与运行流程

1. 应用启动时读取内置资料和本地缓存。
2. 两份资料都通过验证时选择版本较新的资料；缓存损坏、版本较旧或读取失败时自动回退内置资料。
3. 首帧显示后自动发起一次后台检查，避免阻塞启动。
4. 发现同版本时只更新“上次检查时间”和来源。
5. 发现新版本时下载到内存并验证，通过后原子写入本地缓存。
6. Controller 替换当前 QuestCatalog 并通知任务中心；“全任务”和进行中任务的英文编号立即刷新。
7. 同一时间只有一个检查任务；自动检查和手动按钮共用进行中的 Future，避免重复下载。

## 数据验证

下载内容必须同时满足：

- 响应为合法 UTF-8 JSON，根节点为对象。
- 文件大小不超过预设上限，任务数不少于 500。
- 每项任务键是正整数游戏 ID。
- `code`、`name`、`desc` 字段类型正确；英文任务编号非空且全局唯一。
- `pre` 缺省时视为空数组；存在时必须只包含非空字符串。
- 所有能解析的前置编号不得形成自引用；未知前置编号允许保留，因为上游可能暂时缺少历史或活动任务。
- 远端版本不得早于当前有效版本。

任一检查失败都不写入缓存，也不替换内存中的当前资料。

## 本地存储与恢复

- 应用支持目录保存任务资料缓存和独立状态文件。
- 写入使用 `.tmp` 临时文件、旧文件 `.bak` 备份和替换后清理的原子流程。
- 应用异常退出后，下次读取会检查目标文件与备份文件，优先恢复最后一份验证有效的数据。
- 状态文件保存版本、完整提交号、内容校验值、来源域名、上次检查 UTC 时间和检查结果。
- 应用支持目录不可用时退化为只读内置资料；更新按钮仍可检查，但保存失败会明确提示且不影响当前资料。

## 设置页交互

在现有“数据更新”区域中，与“未卜先知资料”并列增加“任务资料”：

- 显示当前资料版本。
- 显示上次检查时间。
- 右侧使用同款金色同步图标按钮。
- 检查期间按钮禁用并显示圆形进度指示。
- 结果对话框区分：已经最新、更新成功、网络失败、资料验证失败、存储失败。
- 更新成功文案说明资料已经立即生效。

## 错误处理

- 主下载源网络失败后尝试备用源。
- HTTP 非 200、超时、响应超限和未授权 URL 归为网络或验证失败。
- 验证失败不再尝试将同一版本的数据写入其他位置。
- 存储失败不改变当前内存资料；已经验证的下载数据不会以未持久化状态临时替换，确保重启前后版本一致。
- 自动检查失败不弹窗，只记录状态；用户手动检查时显示结果对话框。

## 测试要求

- Dataset：合法数据、数量下限、重复编号、字段错误、自引用和版本解析。
- Store：缓存优先级、损坏回退、旧缓存拒绝、原子替换、备份恢复和状态持久化。
- UpdateService：主要源、备用源、同版本、新版本、防降级、超时、超限、校验失败和存储失败。
- Controller：检查去重、立即应用、状态通知和失败时保持旧资料。
- 设置页：版本和时间显示、按钮加载态、成功与各种失败文案。
- 任务中心：Controller 更新后任务英文编号、说明及前后置关系无需重启即可刷新。

## 热重载说明

本功能会新增启动依赖注入、持久化存储和本地化文案。开发完成后的第一次验证需要点击绿色重新加载按钮；不需要重新打 APK。之后仅修改 Dart 界面代码时仍可使用黄色闪电热重载。
