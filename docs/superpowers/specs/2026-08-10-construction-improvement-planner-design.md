# 建造详情页改修规划设计

## 目标

在现有「建造」详情页增加「建造／改修」模式切换。「建造」模式完整保留当前代码、布局与交互；「改修」模式参考 poi 的装备改修功能，按星期展示当天可改修装备，并支持收藏和仅看收藏。

本功能只读取本地资料并展示信息，不操作游戏、不发送游戏 API 请求，也不改变现有建造状态解析。

## 数据来源与边界

- 改修资料改用 [`auluu/PlannerRemoteRawData`](https://github.com/auluu/PlannerRemoteRawData)。页面交互仍参考 poi 的每日改修功能，但不再读取 poi 插件的数据文件。
- 上游由 `data_manifest.json` 描述版本和完整文件清单。App 使用以下 8 个文件：`equip_base_cost.json`、`equipment_upgrade_path.json`、`improvement_arrangement.json`、`improvement_consume_item.json`、`improvement_consume_step.json`、`improvement_upgrade_cost.json`、`improvement_upgrade_target.json` 和 `material.json`。
- 内置一份经过联合校验和规范化的基线快照，确保首次安装和离线状态可用。
- 装备名称和图标通过上游装备 ID 关联游戏主数据；主数据暂不可用或图片资源缺失时，使用装备 ID 和项目现有未知装备图标兜底。
- 构建同步脚本与 App 更新服务共用同一套解析和验证规则，避免构建期与运行期产生不同结果。
- 上游仓库当前未声明 LICENSE。`assets/data/THIRD_PARTY_DATA.md` 必须记录来源、提交号、同步时间和许可证状态；公开分发前需取得或确认数据使用授权。

## 手动更新本地库

- 在设置的数据更新区域增加「改修资料」区块，布局、版本信息、状态提示和手动更新按钮与「未卜先知地图资料」及「全任务资料」保持一致。
- 用户点击「检查改修资料更新」后，更新服务先通过 GitHub API 查询 `auluu/PlannerRemoteRawData` 默认分支的最新提交号。
- 所有 JSON 均从该不可变提交号对应的 `raw.githubusercontent.com` 地址下载；`cdn.jsdelivr.net` 作为同一提交号的备用源。禁止直接混合读取可变的 `main` 分支文件。
- 下载 `data_manifest.json` 后必须验证 `version_complete == true`、版本日期不回退、文件清单与允许列表完全一致，再下载其余 8 个文件。
- 更新服务限制单文件和整套资料大小，拒绝重定向、非 HTTPS 地址、未知主机、未知文件、重复主键、断裂外键、非法星期、负数消耗和缺少关键数据的快照。
- 8 个文件全部下载并通过联合校验后，先规范化为单一运行时快照，再通过现有存储抽象原子替换缓存。任何文件下载、解析、验证或保存失败，都保留当前有效版本。
- 更新成功后立即替换 Controller 中的数据并刷新当前改修表格，不要求重启 App。
- 本地状态保存数据版本、上游提交号、内容 SHA-256、最近检查时间、最近更新结果和来源主机，供设置页展示。
- 内置快照、缓存快照和刚下载快照采用同一个 `ImprovementDataset` 模型；启动优先读取有效缓存，失败时自动回退内置版本。

## 页面模式

- 建造页默认进入「建造」模式，现有 `ConstructionDockStatusView` 原样保留。
- 工作区右上角增加 `260 × 38` 分段按钮，复用「入渠修理／泊地修理」的容器、颜色、圆角、字号与点击区域。
- 两个按钮文字为「建造」和「改修」，两项等宽；文字较短不改变四字宽按钮的整体尺寸标准。
- 模式状态由工作区 Shell 持有，标题栏和详情内容使用同一状态，避免两个入口不同步。

## 星期与收藏

- 改修模式顶部按「周一」至「周日」排列 7 个切换按钮，末尾增加圆形五角星按钮。
- 首次进入默认选择当前日本标准时间（JST）对应的星期，与 poi 的每日切换规则一致。
- 切换星期后显示该日可用的改修资料；收藏筛选状态在星期切换时保留。
- 圆形五角星未选中时显示当天全部装备，选中时只显示当天收藏。
- 每行第一列提供收藏五角星。收藏键为装备 ID，同一装备在不同星期共用收藏状态。
- 收藏使用 `SharedPreferences` 持久化；读写失败时当前会话仍可操作，并保留上一次有效内存状态。

## 表格列与内容

表格固定为一件装备一行，列顺序如下：

1. 收藏
2. 装备名字
3. 基础消耗
4. `0 → +6`
5. `+6 → MAX`
6. 进化消耗
7. 秘书舰
8. 可进化
9. 进化装备

具体显示规则：

- 「收藏」显示可点击五角星。
- 「装备名字」显示装备图标和名称。
- 「基础消耗」在同一行依次显示燃料、弹药、钢材、铝土图标及数值，不显示「燃／弹／钢／铝」文字说明。
- `0 → +6`、`+6 → MAX` 和「进化消耗」不使用胶囊或内嵌卡片，直接显示消耗装备图标、装备名字和 `×数量`；无消耗装备时显示 `—`。
- 「秘书舰」合并展示所选星期可用的秘书舰名称，去重后保持资料顺序。
- 「可进化」只显示「可进化」或 `—`。
- 「进化装备」显示目标装备图标和名称；不可进化时显示 `—`。
- 同一装备在同一天存在多条改修路线时仍只占一行。各单元格按资料顺序纵向或换行排列去重后的内容，不复制装备行。

## 与持有一览统一

- 抽取或复用「持有一览」的冻结表格基础组件，不复制一套近似实现。
- 表头高度统一为 `34`，基础行高统一为 `44`，单元格水平内边距、字体、边框颜色、交替底色、滚动条和裁剪行为与持有一览一致。
- 行高沿用持有一览的动态计算规则：`44` 为最小值；当秘书舰、多路线消耗或进化装备需要换行时，以所有单元格中最高内容为准增加行高，并保持冻结区与滚动区逐行对齐。
- 横向滚动时冻结「收藏」和「装备名字」两列；纵向滚动时两列与主表同步，表头保持固定。
- 手机竖屏、手机横屏、平板竖屏和平板横屏使用同一张表，不降级成卡片；窄屏通过横向滚动查看后续列。

## 组件与职责

- `ImprovementDataset`：解析并联合校验 8 个上游文件，生成统一运行时快照。
- `ImprovementProjection`：按 JST 星期筛选数据、按装备 ID 合并路线、去重秘书舰和消耗项。
- `ImprovementFavoritesStore`：读取和保存收藏装备 ID。
- `ImprovementPlannerController`：持有星期、收藏集合和仅看收藏状态，向界面提供稳定投影。
- `ImprovementDatasetStore`：保存版本元数据和规范化缓存，写入时使用临时文件加原子替换。
- `ImprovementDatasetUpdateService`：固定上游允许列表、下载不可变提交快照、执行联合校验并返回结构化更新结果。
- `ConstructionImprovementModeSelector`：复用修理模式按钮的尺寸和视觉参数。
- `ImprovementPlannerView`：星期栏、收藏筛选和冻结表格。
- `ImprovementDatasetUpdateSection`：在设置页展示版本、最近检查结果和手动更新按钮。
- 通用冻结表格组件：由持有一览现有 `_FrozenTable` 提取为可复用组件，持有一览和改修表格共同使用。

各组件通过明确的数据模型通信。数据解析、筛选合并、收藏持久化和表格渲染可以独立测试。

## 错误与空状态

- 内置资料缺失或校验失败：改修模式显示「改修资料不可用」，建造模式不受影响。
- 远程更新失败：设置页显示网络、验证或存储错误；当前有效资料继续使用。
- 远程版本与当前版本一致：显示「改修资料已经是最新版本」。
- 远程版本更新成功：显示新旧版本号并立即刷新页面。
- 当天没有可改修装备：显示「当天没有可改修装备」。
- 开启仅看收藏但结果为空：显示「当天没有收藏的改修装备」。
- 装备主数据尚未同步：名称显示为 `#装备 ID`，图标使用项目现有未知装备图标；秘书舰使用上游 `secretary_label` 显示。
- 收藏保存失败：不清空界面状态，不阻断浏览。

## 本地化

新增简体中文、正體中文和日文文案。装备与秘书舰名称首版按资料原文显示；界面标签必须走现有本地化资源。

## 测试与验收

- 数据集测试：8 个文件的字段类型、主键唯一性、外键完整性、星期字段、阶段 ID、资源非负值、引用装备和进化目标合法性。
- 更新测试：最新提交查询、不可变 URL、备用源、版本不回退、文件清单白名单、大小限制、单文件失败、联合校验失败、原子保存失败、缓存恢复和即时替换。
- 投影测试：JST 星期映射、当天筛选、多路线合并、秘书舰去重、收藏筛选和稳定排序。
- 收藏测试：读取、写入、失败回退和跨星期共享。
- 模式测试：默认建造、切换改修、返回建造后现有建造内容与状态不变。
- 表格测试：9 列顺序、四资源同一行、阶段单元格无胶囊、进化两列、双冻结列和双向滚动。
- 统一性测试：持有一览与改修表格共享 `34` 表头高度、`44` 最小行高和同一冻结表格组件。
- 响应式测试：`390 × 780` 手机竖屏、`780 × 390` 手机横屏、`768 × 980` 平板竖屏、`1024 × 720` 平板横屏无 overflow 异常。
- 设置测试：改修资料版本、最近检查时间、检查中状态、成功提示和三类失败提示与现有资料更新区块一致。

## 热重载说明

纯 Dart 代码和本地化改动可以先点黄色闪电查看。新增内置快照、Controller 初始化和 `pubspec.yaml` 资产声明后，需要点一次绿色重新加载；不需要重新构建 APK。后续通过手动更新按钮替换本地库时会立即生效，不需要点黄色或绿色图标。
