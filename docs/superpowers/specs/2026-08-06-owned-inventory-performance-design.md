# 持有一览性能优化设计

## 目标

在不改变持有一览现有视觉设计、筛选排序规则、冻结首列、横向滚动条和装备动态行高行为的前提下，降低首次进入、切换分类、排序、纵向滚动以及游戏状态刷新时的卡顿。

## 当前瓶颈

1. `_FrozenTable` 使用 `SingleChildScrollView + Column` 一次性构建全部舰娘或装备行，屏外行不会延迟创建。
2. 舰娘头像没有指定解码缓存尺寸；大量缩略头像可能按资源原尺寸解码。
3. 页面每次构建都会同时生成舰娘投影和装备投影，即使其中一页处于隐藏状态。
4. 页面监听完整 `GameStateController`；与库存无关的资源、任务和战斗状态变化也会触发整张表重建。
5. 装备页每次构建都会重新测量全部改修、熟练度和着装文本并计算动态行高。
6. 冻结列、正文和表头依靠多个滚动控制器逐帧同步；在完整大列表上会放大布局与绘制成本。

## 设计方案

### 1. 惰性冻结表格

保留现有表头、列宽、边框、冻结首列和横向滚动结构，将冻结列与正文的完整 `Column` 改为按需创建的惰性列表。

- 舰娘页使用固定 56 dp 行高，并给惰性列表提供固定行高信息。
- 装备页继续使用每条装备独立的动态行高，冻结列和正文读取同一份行高数组。
- 冻结列与正文只构建视口及少量缓存区内的行；目标通常为约 15～25 行，而非全部库存。
- 两侧列表保持同一垂直偏移，右侧仍负责用户滚动，冻结侧不可直接滚动。
- 横向表头继续跟随正文横向偏移，底部横向滚动条保持常驻。
- 行内容外层增加重绘隔离，避免单行图片完成加载时扩大到整张表重绘。

### 2. 仅生成当前标签的数据

页面只计算当前显示标签所需的投影：

- 舰娘标签只调用 `shipRows()`。
- 装备标签只调用 `equipmentGroups()`。
- 切换标签、分类或排序时只更新对应结果。
- 不引入分页，不改变筛选结果数量和排序语义。

### 3. 库存派生数据缓存

在页面状态中缓存舰娘行、装备分组和装备行高。

- 舰娘缓存键包含：舰娘集合、舰队集合、舰娘主数据、舰种主数据、装备实例、装备主数据、舰娘分类、排序字段和排序方向。
- 装备缓存键包含：装备实例、舰娘集合、装备主数据、舰娘主数据和装备分类。
- 装备行高缓存额外包含可用列宽、文字缩放比例和装备分组结果。
- 只有缓存键中的依赖发生变化才重新生成；资源、任务、战斗预告等状态变化复用原结果。

缓存使用 `GameState` 中不可变集合的引用身份作为快速失效依据，并由筛选、排序和布局参数补足语义依赖。不复制或修改游戏状态数据。

### 4. 缩小状态监听范围

仍由 `GameStateController` 提供真实数据，但控制器通知后先比较库存相关引用：

- `ships`
- `fleets`
- `slotItems`
- `masterShips`
- `masterShipTypes`
- `masterSlotItems`
- `serverOrigin`

只有这些依赖影响当前页面时才更新持有一览的昂贵表格子树。顶部数量和当前标签与同一库存快照一致。任务、资源、战斗状态和时间戳变化不会重建表格。

### 5. 舰娘头像缩略图解码

`ShipPortrait` 增加可选的缩略图解码尺寸参数。持有一览根据头像实际显示高度和设备像素比传入 `cacheHeight`：

- 逻辑显示高度保持 51 dp，裁切位置和渐变外观不变。
- 解码高度按实际绘制高度乘设备像素比并向上取整。
- 其他需要较大头像的页面不传参数，保持现有清晰度与缓存键。
- 惰性列表销毁屏外行后，不再让全部舰娘头像同时保持活动状态。

### 6. 装备行高缓存

将装备行高计算结果与装备分组、文字缩放和表格列宽绑定：

- 相同输入直接复用行高列表。
- 改修／熟练度与着装情况继续完整换行并纵向居中。
- 字体缩放、列宽或装备数据发生变化时完整失效并重新测量。
- 冻结列与正文始终共用同一行高，防止长期滚动后错位。

### 7. 滚动与绘制优化

- 同步滚动增加重入保护，避免两侧控制器互相触发跳转。
- 仅在目标偏移确实变化且目标控制器已有视口时同步。
- 表头、冻结列和正文保留各自裁切边界。
- 行级 `RepaintBoundary` 隔离头像、图标加载和单行状态绘制。
- 本轮不移除 `ShipPortrait` 的渐隐外观；如性能采样仍显示光栅线程超预算，再单独评估用渐变覆盖替代 `ShaderMask`。

## 数据流

1. 控制器发出状态通知。
2. 页面提取库存依赖快照并与上次快照比较。
3. 无关状态变化：复用当前表格与派生数据。
4. 库存相关变化：仅使受影响的当前标签缓存失效。
5. 标签、筛选或排序变化：生成对应派生数据。
6. 惰性冻结表格仅创建视口附近行。
7. 可见舰娘头像按缩略尺寸请求和解码。

## 测试与验收

### 自动化行为测试

- 大舰娘数据集首次渲染时，屏外舰娘行和头像尚未创建；滚动后目标行才创建。
- 大装备数据集首次渲染时，屏外装备行尚未创建；动态高度行滚动后能正确出现且冻结列对齐。
- 舰娘页不生成装备分组，装备页不生成舰娘排序结果。
- 仅资源、任务或战斗状态变化时，库存派生结果与可见行不重建。
- 舰娘、舰队或装备变化时，对应缓存正确失效。
- 持有一览头像传入与设备像素比匹配的解码高度。
- 装备行高在输入不变时复用，在文字缩放或数据变化时失效。
- 原有筛选、排序、冻结列、横向滚动和多行着装测试全部继续通过。

### 性能验收

- 使用真机 Profile 模式分别记录舰娘页首次进入、连续纵向滚动、切换分类、切换装备页和游戏状态更新。
- 目标是正常滚动时绝大多数 UI 与 Raster 帧保持在设备刷新率预算内；不以 Debug APK 的帧时间作为发布结论。
- 舰娘页初次构建的行和网络头像数量应接近视口缓存范围，而不是账号持有总数。

## 不在本轮范围

- 不修改持有一览视觉设计与文字。
- 不改成分页加载。
- 不引入第三方表格组件。
- 不改变装备分类、排序规则或数据来源。
- 不全局调整 Flutter 图片缓存上限。
