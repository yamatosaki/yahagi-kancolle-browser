# 战果日历与自动状态 Demo 设计

## 目标

将战果 Demo 的“近期战果”柱状图改为月历，并将计划区改为 EO／任务自动状态总览，同时明确跨设备数据的可靠性边界。

## 日历

- 当前月按星期一至星期日排列为 7 列日期网格。
- 日期单元格上方显示日数，下方显示当天总战果，保留一位小数。
- 当天总战果公式：`提督经验增量 × 7 ÷ 10000 + 当日完成 EO 战果 + 当日领取战果任务`。
- `0.0` 表示当天有完整记录但没有新增战果；`—` 表示未来日期或没有可用记录。
- 今天使用客户端金色选中态；其他有数据日期可点击。
- 点击日期后，在日历底部显示该日来源明细：经验战果、EO 战果、任务战果。
- Demo 使用 2026 年 8 月示例数据，日期与数值布局参考 `poi-plugin-senka-calc 5.5.0` 的 Calendar，但数字采用本设计的总战果口径，而不是插件仅计算经验战果的口径。

## 自动状态总览

原“可用战果计划”改为一行四格：

1. 已完成 EO
2. 未完成 EO
3. 已完成任务
4. 未确认任务

每格显示项目数量和战果合计。点击格子后，在下方列表展示对应项目名称、战果和状态来源。

## 数据判定

### EO

- 从 `/kcsapi/api_get_member/mapinfo` 的 `api_map_info` 读取地图状态。
- `api_cleared > 0` 判为已完成，否则判为未完成。
- EO 状态属于服务器权威数据；首次观察到由未完成变为完成时，记录到当天日历。
- Demo 覆盖 1-5 至 7-5 的八张 EO 地图，并提供“模拟自动同步”展示状态变化。

### 战果任务

- 维护 `poi-plugin-senka-calc 5.5.0` 使用的七个季度战果任务 ID 与战果值。
- 监听 `/kcsapi/api_req_quest/clearitemget`；本机观察到领取时，记录为已完成任务并计入当天日历。
- 其余任务归入“未确认任务”，不称为“未完成任务”。
- 原因是其他设备完成并领取后，本机任务列表无法区分“未接取”和“已经领取”。
- 页面固定显示提示：跨设备完成的任务可能没有被本机记录；手动校准只能修正战果总量，不能反推出具体任务。

## Demo 交互

- 保留五档设备尺寸切换、跨设备缺口开关、目标编辑与手动校准。
- 新增“模拟自动同步”按钮：每次触发模拟一张 EO 完成和一个战果任务被领取，并同步更新四格统计、项目列表、预计战果与当天日历。
- 四格状态可点击切换列表；选中态使用客户端金色描边。
- 日期可点击切换当日战果来源明细。
- 重复同步不得重复计入同一个 EO 或任务。

## 响应式规则

- 大、小平板：当前战果与目标位于上区，四格状态和项目列表位于中区，日历占底部通栏。
- 平板竖屏：各区单列滚动，四格允许保持 4 列紧凑布局。
- 手机横屏：保留当前战果、目标和四格总览；隐藏项目明细与完整日历，避免核心操作被压缩。
- 五档尺寸均不得产生页面级横向溢出。

## 验收

- 页面不存在旧柱状趋势图结构。
- 日历含 7 列星期头、日期、每日总战果与可切换的来源明细。
- 四格标题严格为“已完成 EO、未完成 EO、已完成任务、未确认任务”。
- 模拟同步后数量、合计、预计战果和当天日历一起变化，重复同步不重复累加。
- EO 明确标记为服务器确认，任务明确标记为本机记录或未确认。
- 原有手动校准、目标编辑、跨设备缺口和五档尺寸交互不回归。
- 自动化状态测试、静态契约和浏览器控制台检查通过。
