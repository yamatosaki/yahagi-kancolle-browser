# 战果 Demo 排行榜信息表设计

## 目标

- 删除容易与服务器快照混淆的预计战果分项和本月目标。
- 用 POI 风格的排行榜信息表直接展示关键名次线与玩家自己的排名。
- 将战果增幅放入独立列并统一左对齐，避免增幅紧跟不同位数的战果而错位。
- 保留 EO／战果任务和战果日历现有交互，并继续满足五档尺寸单屏无滚动展示。

## 页面结构

横屏四档采用左侧两张卡、右侧整列日历：

```text
┌────────────────────┬──────────────────────────┐
│ 战果信息           │                          │
│                    │        战果日历          │
├────────────────────┤                          │
│ EO 与战果任务      │                          │
└────────────────────┴──────────────────────────┘
```

- 左侧仍占 42%，右侧仍占 58%。
- 横屏左侧两行按 `43% / 57%` 分配给“战果信息”和“EO 与战果任务”。
- 平板竖屏改为 1×3：战果信息、EO 与战果任务、战果日历，三行按 `.62fr / .78fr / 1.25fr` 分配。

## 删除内容

- 删除“预计当前战果”主数值及当前顺位胶囊。
- 删除“服务器已结算”“本机可确认未结算”“已计划战果”三项。
- 删除“本月目标”、目标输入、预计最终、距离目标和进度条。
- 删除这些区域对应的渲染逻辑；战果计算历史数据可以继续支持日历和任务状态，但页面不再渲染旧摘要。

## 战果信息表

表格使用三列，全部左对齐：

```text
顺位                 战果      
5                    4,755     ↑0
20                   —         —
100                  —         —
501                  1,144     ↑0
当前 3,874  ↓42      108       ↑78.8
```

- 第一列表头为“顺位”。
- 第二列表头为“战果”。
- 第三列不显示表头文字，但为整列保留固定布局空间。
- 所有数值启用等宽数字。
- `5`、`20`、`100`、`501` 是固定排行榜参考线。
- 玩家行在顺位数字前显示“当前”胶囊，并使用与其他行不同的背景和边框强调。
- 固定参考线的第三列表示该顺位战果相对上次快照的增幅。
- 玩家行第三列表示排行榜快照后的本机新增战果，例如 `↑78.8`。
- 缺少记录时，战果和增幅均显示 `—`，不得显示 `NaN` 或 `undefined`。

## 玩家顺位变化

- 玩家顺位变化显示在第一列的顺位数字之后，不单独增加第四列。
- 排名提升，即顺位数字变小：绿色 `↑` 加变化量，例如 `3,832 ↑42`。
- 排名下降，即顺位数字变大：红色 `↓` 加变化量，例如 `3,874 ↓42`。
- 顺位不变：灰色 `→0`。
- 缺少上次顺位：显示当前顺位但不显示变化，避免制造推断数据。
- 固定参考线本身不显示顺位变化，因为 `5/20/100/501` 是查询位置而非同一玩家。

## 刷新交互

- 标题栏保留“手动校准”按钮。
- HTML Demo 点击后模拟收到新的排行榜快照：
  - 更新玩家当前顺位及相对上次的方向和变化量；
  - 更新玩家服务器战果和第三列的本机新增战果；
  - 更新固定名次线的战果与增幅；
  - 更新最后刷新时间；
  - 不改变 EO／任务和日历选择状态。
- Demo 初始快照固定为：第 5 名 `4,755 ↑0`、第 20 名 `—`、第 100 名 `—`、第 501 名 `1,144 ↑0`、玩家 `当前 3,874 ↓42 / 108 / ↑78.8`。
- 校准成功后的快照固定为：第 5 名 `4,828 ↑73`、第 20 名 `4,145 / —`、第 100 名 `3,072 / —`、第 501 名 `1,180 ↑36`、玩家 `当前 3,832 ↑42 / 112 / ↑4.2`。
- “模拟自动同步”继续模拟本机捕获 EO／任务完成；它更新任务分组、日历和玩家行第三列的本机新增战果，不凭本机数据推算顺位。
- “模拟其他设备游玩”继续表示本机记录可能缺失；不在排行榜表中加入辅助说明文字。

## 视觉规则

- 三列在所有尺寸统一使用 `48% / 27% / 25%`，紧凑横屏也不得合并第二、三列。
- 第二列战果与第三列增幅从各自统一的左边界开始。
- 正向变化使用绿色，负向变化使用红色，不变和缺失数据使用灰色。
- 玩家行高亮不得影响列对齐。
- 表格字号不得小于当前日历每日战果字号；手机横屏中不得靠横向滚动展示。

## 数据模型

- 排行榜参考行包含：`rank`、`senka`、`previousSenka`。
- 玩家快照包含：`rank`、`previousRank`、`senka`、`localDelta`。
- 顺位变化由纯选择器计算：
  - `previousRank - rank > 0` 为提升；
  - `previousRank - rank < 0` 为下降；
  - 等于零为不变。
- 固定参考线增幅为 `senka - previousSenka`。
- 所有缺失或非有限数值在展示选择器中转换为 `null`，由 UI 统一渲染为 `—`。

## 验收标准

- 页面中不存在旧三项战果分项和本月目标卡。
- 战果信息表准确显示 `5/20/100/501/当前玩家` 五行。
- 表格只有“顺位”“战果”两个可见表头，第三列表头为空。
- 第二列战果和第三列增幅分别左对齐；不同位数不会改变增幅的起始位置。
- 玩家顺位提升、下降、不变和缺少历史四种情况均按规则显示。
- 战果缺失时显示 `—`，页面中不出现 `NaN` 或 `undefined`。
- 点击手动校准后排行榜快照、顺位方向、战果增幅和更新时间同步更新。
- 自动同步后 EO／任务分组、日历和玩家本机新增战果正确更新，顺位不被本机推算修改。
- 点击任务胶囊仍能进入对应“全任务”详情并返回。
- 1280×680、1024×600、800×1100、844×390、740×360 五档中，内容、卡片、表格、状态行和日历均无滚动或裁切。
