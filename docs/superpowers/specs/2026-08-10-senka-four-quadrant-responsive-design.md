# 战果 Demo 四象限响应式布局设计

## 目标

- 五档设备预设均在一个画面内展示全部核心信息，不依赖页面滚动。
- 手机横屏与紧凑横屏必须直接看到完整战果日历。
- 删除所有尺寸中的排名来源、手动校准说明等辅助文字。
- 保留现有数据计算、手动校准、目标输入、自动同步、状态选择和日期选择交互。

## 核心信息范围

页面只保留以下四个区域：

1. 当前战果：预计当前战果、服务器已取得、本机可确认未结算、已计划战果。
2. 本月目标：目标输入、预计最终战果、距离目标、三段进度和图例。
3. EO 与任务：已完成 EO、未完成 EO、已完成任务、未确认任务。
4. 战果日历：星期、完整 6 行日期、每日战果和选中日期的一行明细。

删除以下内容：

- 排名数据来源说明。
- 手动校准不会主动修改游戏数据等说明。
- EO 与任务的长项目列表、列表标题和卡片底部提示。
- 其他不影响数值理解和操作的辅助文字。

## 横屏及平板布局

大平板、小平板／折叠屏、手机横屏和紧凑横屏统一使用 2×2 四象限：

```text
┌───────────────┬───────────────┐
│ 当前战果      │ 本月目标      │
├───────────────┼───────────────┤
│ EO 与任务     │ 战果日历      │
└───────────────┴───────────────┘
```

- 两列默认接近等宽；可根据数值长度略微增加左列宽度。
- 两行按日历最低可读高度分配，日历所在下行不得低于完整 6 行日期所需高度。
- EO 与任务使用 2×2 状态格，不再显示项目长列表。
- 当前战果的 3 项构成横向排列；手机两档缩小间距和字号，但不隐藏数值。
- 日历在右下角完整显示，不使用内部或页面纵向滚动。

## 平板竖屏布局

平板竖屏使用 1×4 纵向排列：

```text
┌───────────────┐
│ 当前战果      │
├───────────────┤
│ 本月目标      │
├───────────────┤
│ EO 与任务     │
├───────────────┤
│ 战果日历      │
└───────────────┘
```

- 四个区域在应用可用高度内一次性排完，应用内容区不滚动。
- 当前战果和本月目标采用紧凑高度；主要高度留给 EO 与任务和战果日历。
- 战果日历保持完整 6 行日期及一行选中日期明细。

## 紧凑规则

- 标题栏、卡片标题、卡片内边距和网格间距按设备尺寸递减。
- 取消依靠 `margin-top: auto` 撑开的说明区域，避免产生大块空白。
- 卡片使用明确的网格行尺寸和 `minmax(0, 1fr)`，子元素不得撑破卡片。
- 页面、应用内容区和四个核心卡片均不得出现非预期滚动条。
- 只允许数字和标签在自身区域内进行省略；核心数值不得被裁切。

## 交互

- 手动校准按钮继续位于应用标题栏。
- 模拟自动同步按钮继续位于 Demo 工具栏。
- 目标输入更新目标差值和进度条。
- EO／任务状态格可选择，选中态继续高亮；不再展开长项目列表。
- 日期按钮继续更新选中日期和日历底部的一行明细。

## 验收标准

- 1280×680、1024×600、844×390、740×360 均为 2×2 布局。
- 800×1100 为 1×4 布局。
- 五档预设均能同时看到四个核心区域，应用内容区 `scrollHeight` 不大于 `clientHeight`。
- 手机两档的完整星期、6 行日期和选中日期明细均位于首屏。
- 五档预设均无页面级横向溢出、卡片遮挡、文字覆盖或核心数值裁切。
- 状态计算测试、目标输入、自动同步、状态选择、日期选择和手动校准交互全部通过。
