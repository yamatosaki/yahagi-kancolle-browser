# Yahagi 1.0.3 修复与优化设计

## 目标

在不改变首页整体视觉结构的前提下，修复登录键盘、退出账号、信息面板比例、任务简报、首页排序、入渠状态同步等问题，并将舰队机制提示和解除 60 FPS 上限纳入 1.0.3。

开发阶段使用常驻 Flutter Debug。每批改动完成后明确提示用户点击黄色闪电（Hot Reload）、绿色按钮（Hot Restart），或停止后重新运行；不在日常修改中反复打 APK。

## 1. 登录页软键盘

- Android Activity 的软键盘策略由 `adjustResize` 改为 `adjustPan`。
- 键盘弹出时保持 Flutter 游戏工作区及 WebView 的原始尺寸，由系统平移当前输入区域，避免游戏画面被压缩。
- 此项涉及 AndroidManifest，生效需要停止 Debug 后重新运行，不能仅依靠 Hot Reload/Hot Restart。

## 2. 退出账号

- 将当前只显示提示的占位入口改成真实退出流程。
- 点击后先显示确认对话框；确认后清除 WebView Cookie、Local Storage 和缓存，再导航到 DMM 登录入口。
- 清理失败时提示明确错误，不显示成功假象。
- 清理只作用于应用内游戏 WebView，不创建第二个 App，也不影响系统浏览器。
- Dart 侧通过 `GameBrowserPort` 暴露可测试的会话清理能力，Android WebView 实现实际清理。

## 3. 推荐显示比例

- 设置名称改为“应用推荐显示比例（游戏与菜单比例 65:35）”，繁体中文和日文同步更新。
- 开启时：游戏区固定 65%，信息面板固定 35%；信息面板宽度滑条显示 35%、置灰且不可操作。
- 关闭时：滑条恢复可用和正常颜色，并恢复用户此前保存的自定义比例。
- 不覆盖用户原有自定义值，以便开关关闭后恢复。

## 4. 任务简报

### 首页

- 保持现有胶囊式任务布局，不在首页展示精确的“次数/目标次数”。
- 标题或紧凑计数胶囊显示服务端进行中任务数与容量，例如 `3/5`。
- 已同步任务仍显示简洁的“进行中 / 50% / 80% / 完成”状态。
- 服务端进行中数量大于本地已知任务数时，用“需进入任务界面同步信息”补足未知项。
- 服务端明确进行中数量为 0 时显示“当前无进行中任务”。尚未获得任务列表或服务端计数时，不误报为空。

### 详情页

- 仿照 poi 的混合进度模型：有已知目标且能通过 API 事件追踪的任务显示精确 `次数/目标次数`；无法可靠精确追踪的任务回退为游戏服务端的阶段进度。
- 1.0.3 优先接入现有捕获范围内可可靠判断的事件；未知或条件复杂的任务不猜测次数。

### 残留修复

- `api_exec_count` 作为进行中任务总数的权威来源。
- 领取奖励、放弃任务后立即移除对应任务并更新计数。
- 访问任务列表时按服务端页面数据和总计数校正缓存，裁剪已经失效的旧任务；跨日刷新继续清理日常、周常等过期记录。

## 5. 首页功能排序

- 适配当前 Flutter `ReorderableListView.onReorderItem` 已经调整过的新索引语义。
- 移除应用层重复的向下拖动索引减一，确保任意项都能放到最后一项之后。
- 增加覆盖“中间项拖到末尾”和“末尾项向上拖”的回归测试。

## 6. 入渠与高速修复状态同步

- 入渠开始和高速修复接口允许成功响应缺少 `api_data`；继续使用请求参数更新入渠槽、舰船耐久、桶和资源。
- 补给监听逻辑不变。
- 增加真实无 `api_data` 响应的回归测试，避免解码阶段提前丢弃事件。

## 7. 首页舰队机制胶囊

- 复用舰队详情已有的机制检测逻辑，包括先制对潜、对空 CI、对空喷进弹幕及适用的舰队特殊攻击。
- 机制信息与等级、舰种/舰名、速度、疲劳属于同一信息层级，使用完全相同的 `MiniBadge` 高度、内边距、圆角和字号。
- 在首页单舰状态行中优先展示最重要的一个机制，避免窄屏过度拥挤；完整机制列表仍可在舰队详情查看。

## 8. 解除 60 FPS 上限

- 设置页改为单一开关“解除 60 FPS 上限”，移除“最高 60 FPS / 跟随屏幕”等分段模式。
- 兼容旧设置：旧的任一启用模式迁移为开，`off` 迁移为关。
- 完全采用 GotoBrowser 的原理：在游戏主脚本执行前拦截脚本响应，将 createjs Ticker 的计时模式替换为 `createjs.Ticker.RAF`。
- 不再通过页面加载后注入脚本，也不强制写入 `framerate = 60`；实际帧率由设备刷新率、WebView 和性能决定。
- 补丁匹配失败时返回原脚本并记录诊断信息，不能阻断游戏加载。
- 开关变更后提示重新加载游戏页面；涉及本轮 Android 原生实现安装时，需要停止 Debug 后重新运行一次。

## 9. 版本与验证

- 版本提升为 `1.0.3`，构建号递增一次。
- 先为每项根因补失败测试，再实现修复。
- 执行 Flutter 单元/组件测试、静态分析和 Android JVM 测试；Android 设备重新连接后，再验证登录键盘、真实退出、入渠同步和高刷新率表现。

## 热重载提示规则

- 纯 Dart UI、文案和状态逻辑：优先提示黄色闪电 Hot Reload。
- 初始化状态、依赖注入或需要重建状态树：提示绿色 Hot Restart。
- AndroidManifest、Kotlin 原生代码或原生通道结构：提示停止 Debug 后重新运行。
- 仅在准备发布 1.0.3 时统一构建 APK，不为每个小修改单独打包。
