# 战果 Demo 响应式溢出修复设计

## 问题证据

- 1280×680：日历网格可用高度约 115px，六行日期内容实际滚动高度约 153px，日期与下方明细发生重叠。
- 1024×600：状态卡可用高度约 143px，内容实际高度约 194px，列表和跨设备提示被裁切。
- 800×1100：整体可滚动且日历空间充足，只有状态卡约 2px 的轻微内容溢出。
- 844×390 与 740×360：CSS 明确隐藏 `.calendar-card`，因此手机横屏无法查看日历。

## 修复原则

- 卡片自身负责约束和滚动，不允许内容依赖外层 `overflow: hidden` 裁切。
- 日历六行按可用高度等分，不使用会撑破容器的固定最小行高。
- 手机横屏保留现有首屏概览，在其下方增加完整日历，通过应用内容区纵向滚动访问。
- 不缩小字体到不可读尺寸，不把手机改成三栏，也不新增概览／日历切换导航。

## 大、小平板

- 状态卡改为五行网格：标题、四格摘要、列表标题、可滚动列表、提示。
- 列表使用 `minmax(0, 1fr)` 获取剩余空间，内部 `overflow-y: auto`；提示始终留在卡片底部。
- 日历卡改为纵向弹性容器，日历主体占剩余空间。
- 日期网格六行使用 `repeat(6, minmax(0, 1fr))`，移除固定 `23px` 最小高度。
- 日期明细保持固定高度并位于网格之后，不允许日期覆盖明细。

## 平板竖屏

- 保留应用内容区纵向滚动。
- 状态列表至少显示三行，其余内容在列表内部滚动。
- 日历保持不低于 300px，日期与明细完整可见。

## 手机横屏

- 应用内容区开启纵向滚动。
- 首屏保持两栏：左侧当前战果跨两行；右侧上方本月目标、下方四格状态。
- 日历作为下一行通栏，不再隐藏；向下滚动即可查看完整月历和日期来源明细。
- 状态项目明细列表仍在手机隐藏，只保留四格摘要，避免右栏过高。
- 日历高度固定为约 220px，星期、六行日期和来源明细均可见。

## 自动验收

- 新增布局检查：对五档预设分别读取状态卡、日历卡、日历网格与应用内容区的 `clientHeight`、`scrollHeight` 和计算样式。
- 大、小平板的状态卡与日历网格不得出现被外层裁切的纵向溢出。
- 手机横屏 `.calendar-card` 必须可见，`.app-content` 必须允许纵向滚动，且内容滚动高度大于视口高度。
- 五档预设不得产生页面级横向溢出。
- 日历、四格状态、自动同步、目标编辑与手动校准交互不回归。
